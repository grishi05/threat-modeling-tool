OWASP reference: LLM Top 10 (2025) and Web Top 10 (2021)

ThreatLens tags each threat with one OWASP category. Risks that come from LLM or AI features use the OWASP Top 10 for LLM Applications (2025); everything else uses the OWASP Top 10 for web applications (2021).

OWASP Top 10 for LLM Applications 2025
LLM01
Prompt Injection
Crafted input, typed directly or hidden in documents and web pages the model reads, overrides the model's instructions.
LLM02
Sensitive Information Disclosure
The model reveals personal data, secrets, or proprietary information from its context, training data, or connected systems.
LLM03
Supply Chain
Compromised or unvetted models, datasets, plugins, or fine-tuning adapters bring in vulnerabilities or backdoors.
LLM04
Data and Model Poisoning
Tampered training, fine-tuning, or embedding data plants bias, backdoors, or wrong behavior in the model.
LLM05
Improper Output Handling
Model output reaches browsers, shells, SQL, or other systems without validation, enabling XSS, injection, or code execution.
LLM06
Excessive Agency
An agent has more tools, permissions, or autonomy than it needs, so a manipulated model can take damaging actions.
LLM07
System Prompt Leakage
Credentials or security logic placed in the system prompt get exposed to users who coax the model into repeating it.
LLM08
Vector and Embedding Weaknesses
Retrieval (RAG) stores leak data across users or tenants, or accept poisoned documents that steer answers.
LLM09
Misinformation
Confident but wrong output (hallucination) is trusted for decisions or shown to users without verification.
LLM10
Unbounded Consumption
No limits on requests, input size, or tokens, which allows runaway costs, denial of service, or model extraction.
OWASP Top 10 2021 (web applications)
A01
Broken Access Control
Users act outside their intended permissions: attackers reach other users' accounts, view sensitive data, or perform admin functions. The most common OWASP risk since 2021.
A02
Cryptographic Failures
Sensitive data (passwords, credit cards, health records) exposed due to weak or missing encryption in transit or at rest.
A03
Injection
Untrusted data is sent to an interpreter as part of a command or query: SQL, NoSQL, OS, and LDAP injection. Attackers can steal, modify, or destroy data.
A04
Insecure Design
Flaws in the architecture itself rather than in the code: missing threat modeling, insecure design patterns, and no security requirements at design time.
A05
Security Misconfiguration
Default credentials, unnecessary features enabled, missing hardening, overly permissive cloud storage. One of the most widespread categories.
A06
Vulnerable & Outdated Components
Using libraries, frameworks, or dependencies with known vulnerabilities. A single outdated package can expose your entire app (see: Log4Shell).
A07
Identification & Auth Failures
Weak passwords, missing MFA, exposed session tokens, credential stuffing. Allows attackers to assume other users' identities.
A08
Software & Data Integrity Failures
Untrusted plugins, libraries, updates, or CI/CD pipeline steps. Includes insecure deserialization, where malicious data objects can lead to code execution.
A09
Security Logging & Monitoring Failures
Without proper logs and alerts, breaches can go undetected for months, and investigators have no evidence to reconstruct what happened.
A10
Server-Side Request Forgery (SSRF)
An attacker makes the server send requests to internal systems, reaching cloud metadata endpoints, internal APIs, or other infrastructure.
